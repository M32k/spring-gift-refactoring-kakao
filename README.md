- **Claude Code**(OMC 설치, manual mode): 문서를 썼다.

### 2. 사용한 프롬프트와 접근 방법

- **목록부터 받고, 확인한 뒤 파일로 쓰기**: AI에게 먼저 들어갈 내용이나 초안을 보여 달라고 했다. 내용을 확인한 뒤에 파일을 만들거나 고치게 했다.
  > 방금 만든 CLAUDE.md를 기준으로 AGENTS.md를 만들 거야. 아직 파일은 만들지 말고, 들어갈 내용부터 보여 줘.

  > README.md에 1단계 AI 활용 기록을 쓸 거야. 아직 파일은 고치지 말고 초안만 보여 줘.
- **manual mode**: 문서 작성을 시작할 때부터 썼다. 1단계는 `src/` 수정 금지라서, 파일이 바뀔 때마다 직접 보고 승인하려고 썼다.
- **범위를 정한 분석 요청**: 주문 흐름 분석을 요청할 때 세 가지를 정했다.
  - 주문 관련 코드만 읽는다.
  - 읽을 것이 15개를 넘으면 먼저 묻는다.
  - 결과를 (확인함)과 (코드로만 판단)으로 나눈다.
- **확인함 / 코드로만 판단 구분**: 결과마다 근거를 표시했다. 직접 요청을 보내 본 결과에는 **(확인함)**, 코드만 읽고 내린 판단에는 **(코드로만 판단)**을 붙였다.
- **확인 방법으로 섹션 나누기**: 확인 필요 목록을 세 섹션으로 나눴다.
  - A: 요청으로 확인함
  - B: 코드로만 확인함
  - C: AI 추정
  - 요청으로 확인한 항목은 A로 옮겼다. 다른 문서가 번호로 가리키기 때문에 번호는 다시 매기지 않았다.
- **작동과 이유 나누기**: 작동을 만드는 코드 위치와, 작동의 의도를 설명하는 근거(주석, 메시지, 이름)를 따로 적게 했다.
- **고치지 않고 기록만**: 버그처럼 보이는 작동도 고칠 방법을 정하지 않고 기록만 하게 했다.
- **용어 사전으로 표현 맞추기**: 용어 사전을 만든 뒤 모든 문서의 표현을 용어 사전에 맞췄다.
- **역할 나누기**: 요청 확인(curl)과 git 명령은 내가 직접 했다. AI는 보낼 요청을 적어 주기만 했다.
- **범위 제한**: 프롬프트마다 "`src/`는 건드리지 마", "다른 부분은 건드리지 마"처럼 고쳐도 되는 범위를 적었다.

### 3. AI가 정리한 내용 중 실제 요청이나 확인으로 고친 것

| AI가 처음 정리한 내용 | 확인한 방법 | 고친 내용 |
|---|---|---|
| C-1(추정): 상품 삭제, 수정에 인증이 없을 것이다 | 로그인 토큰 없이 curl로 삭제, 수정 요청 | A 섹션 11번, 18번으로 옮김 |
| C-2(추정): 재고보다 많이 주문하면 오류가 날 것이다 | 재고 50인 옵션에 51개 주문 | A 섹션 12번으로 옮김. 3번(포인트 부족)과 달리 재고와 포인트가 그대로라는 차이를 덧붙임 |
| C-3(추정): 관리자 화면에 인증이 없을 것이다 | 브라우저 접속과 curl로 회원 수정, 충전, 삭제 요청 | A 섹션 13번, 22번으로 옮김 |
| B 섹션 14번(코드로만 판단): 주문 알림을 본인에게 보낸다 | 카카오 로그인 회원으로 주문해 본인 카카오톡 확인 | A 섹션으로 옮김 |
| B 섹션 8번(코드로만 판단): 주문 흐름의 "위시 정리"가 구현되지 않았다 | 맥북을 주문한 user1의 위시를 curl로 확인 | 주문 흐름 문서에 (확인함)으로 표시함. open-questions 8번을 A 섹션으로 옮김 |
| 사용자 스토리 16번 제목에 형식 예시의 목적을 "왜"로 넣음 | 코드에서 근거를 찾음. 근거 없음 | "왜: 확인 필요"로 되돌림 |
| 사용자 스토리의 "확인한 응답" | 각 API에 요청을 보냄 | 실제로 본 응답으로 채움(`16067bd`) |
| open-questions 15–17번을 AI가 curl로 직접 확인함. 내가 직접 확인한 결과와 섞임 | 내가 직접 다시 요청을 보냄 | 확인 방법을 "직접 curl로 확인함"으로 고침. 이후 요청 확인은 내가 하고, AI는 실행하지 않게 정함(AGENTS.md) |
| "토큰", "등록"을 넓은 뜻으로 씀 | 용어 사전과 대조 | 로그인 토큰과 카카오 액세스 토큰, 등록과 회원 가입을 구분해 고침(`dbb526c`) |
| 문서마다 기준 브랜치가 `practice-interface`와 `M32k`로 섞임 | 브랜치 확인 | `M32k`로 통일(`4d89d56`) |
| AGENTS.md 초안에서 "카카오 키에도 기본값이 들어 있다"고 함 | `application.properties`를 직접 확인 | 카카오 키는 기본값이 비어 있고 `JWT_SECRET`만 예시 값이 있음. open-questions 23번으로 기록 |
| AI가 git 명령을 실행함 | – | git 명령은 내가 터미널에서 직접 하게 정함(AGENTS.md) |

#### `/init`이 만든 CLAUDE.md에서 AGENTS.md로 옮기지 않은 내용

AGENTS.md에는 저장소를 읽어서 알 수 없는 것과 다시 찾는 데 오래 걸리는 것만 남겼다. 지금 CLAUDE.md는 `@AGENTS.md` 한 줄이다.

| CLAUDE.md 내용 | 뺀 이유 |
|---|---|
| 빌드는 Kotlin 설정이지만 코드는 전부 Java이고, `src/main/kotlin`은 비어 있다 | `build.gradle.kts`와 `src/` 폴더 구조를 보면 바로 알 수 있다 |
| ktlint는 Kotlin만 검사해서 지금은 아무것도 검사하지 않는다 | `build.gradle.kts`의 플러그인 설정에서 알 수 있다 |
| H2 인메모리 DB와 Flyway로 뜨고, 재시작하면 데이터가 초기화된다 | `application.properties`에 datasource 설정이 없다는 점과 `db/migration`에서 알 수 있다 |
| 테스트는 아직 없다 | `src/test`를 보면 바로 알 수 있다. 2단계에서 바뀔 내용이기도 하다 |
| 문서는 한국어 평서문(~다)으로 짧게 쓴다 | 기존 문서를 보면 알 수 있다 |
| 용어는 용어 사전을 따르고, 문서에는 한국어 이름, 코드에는 영어 이름을 쓴다 | `docs/glossary.md` 첫머리에 적혀 있다. 문서 위치와 규칙 섹션이 대신한다 |
| **(확인함)** / **(코드로만 판단)** 표시 | 정의가 주문 흐름 문서 머리말에만 있고, 주문 흐름 문서는 넣지 않기로 했다. 대신 "요청 확인은 사용자가 한다"는 결정을 남겼다 |
| 작업 문서는 `docs/work/NN-주제/`에 두고 머리말을 붙인다 | 주문 흐름 문서에만 해당하는 규칙이라 뺐다 |
| 코드 위치는 `파일:줄` 형식으로 쓴다 | `docs/open-questions.md` 머리말에 적혀 있다 |
| user-stories의 "왜: 확인 필요"와 "확인한 응답"은 실제로 본 것만 쓴다 | `docs/user-stories.md` 머리말에 적혀 있다 |
| 커밋 메시지는 `접두사: 한국어 요약` 형식으로 쓴다 | `git log`로 알 수 있다 |
